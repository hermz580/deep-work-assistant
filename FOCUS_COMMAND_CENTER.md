# Focus Command Center

The Focus Command Center is a local browser interface for the existing Deep Work Assistant engine. It reads and writes the same local JSONL and SQLite files as the CLI; it does not create a separate cloud account or duplicate data store.

## Start it on Windows

From the repository folder, double-click:

```text
run_focus_command_center.bat
```

Or run either command:

```bash
python -m deep_work_assistant.web_ui
```

```bash
deep-work-ui
```

The interface opens at:

```text
http://127.0.0.1:8765
```

The server binds to localhost by default. Other devices cannot access it unless you deliberately change the `--host` option.

## Functional surfaces

### Command

- Start and stop a Pomodoro focus cycle.
- Select 25, 50, or 90 minutes.
- Link the cycle to a real Kanban card.
- Pause, resume, advance, or stop the persisted timer.
- Start or stop a Deep Work Assistant process launched by the UI.
- See the current adaptive hydration, stretch, and meal schedule.
- Read the actual productivity score, streak, local profile, insights, and 14-day focus trend.

### Work Board

- Create, edit, delete, and drag cards between valid workflow columns.
- Store priority, tags, description, application pattern, and window-title pattern.
- Display the real time logged against each card.
- Reuse the existing `~/.deep_work_assistant/kanban.db` database.

### Sessions

- Read completed focus sessions from the existing history file.
- Show application, duration, end reason, and reminder activity.
- Compare recorded human-active and agent-active time.

### Recovery

- Run an actual timed two-minute box-breathing reset.
- Show recommendations generated by the analytics engine.
- Show the real 30-day work-category distribution.

## Visual systems

The same functional interface includes four switchable surface systems:

1. Cinematic Material
2. Afrofuturist Cosmic
3. Liquid Motion
4. AI Core

The selected theme is stored in the browser's local storage. Changing themes does not change or transmit assistant data.

## Current boundaries

- The assistant status control knows about the process it launched. It cannot reliably identify a separate assistant process started in another terminal.
- The interface is a localhost browser application, not a native Windows executable.
- Existing reminder windows and the enforced stretch overlay remain separate Windows UI processes.
- The existing stretch overlay still covers only the primary monitor.
- Actual notification, text-to-speech, and Windows foreground-activity behaviour must be verified on a Windows machine.
